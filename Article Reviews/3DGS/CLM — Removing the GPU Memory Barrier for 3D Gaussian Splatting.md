При обучении 3DGS все гауссианы загружаются на видеокарту. Поэтому сложно масштабировать сцены на огромное представление в виде гауссиан.

Авторы статьи, в отличие от других методов оптимизации (добавления GPU или уменьшения качества), хотят использовать только необходимые гауссианы на каждой итерации, а оставшиеся хранить на CPU. Однако стоит учесть, что перенос с CPU на GPU — дорогостоящая операция.

Они разработали новую стратегию оптимизации на основе наблюдений над процессом обучения 3DGS:

1. Набор гауссиан, доступных каждому виду, можно вычислить заранее
2. Существует связь между видами, что позволит кэшировать некоторые гауссианы
3. Просмотр в одном и том же регионе имеет доступ к одним и тем же гауссианам, поэтому нужно спланировать процесс обучения так, чтобы максимизировать перекрывающиеся доступы при последующих итерациях и минимизировать коммуникации
4. Мы можем дополнительно использовать пространственную локальность для пересечения градиентных вычислений и значительной части обновления гауссового параметра

## 2.Background and Motivation

### 2.1.Novel View Synthesis and 3D Gaussian Splatting

Для представления одного гауссина нужно 59 параметров = 3 (позиция гауссиана) + 4 (вращение) + 3 (масштаб) + 48 (SH - цвет) + 1 (прозрачность)

Процесс обучения 3DGS: 
1) начальное облако точек получают либо произвольно, либо через COLMAP
2) рендерим новый вид с одной или нескольких известных камер
3) обрезаем ненужные гауссианы (frustrum culling) и проецируем их на экран
4) сравниваем с исходным изображением и используем метод обратного распространения ошибки для обновления параметров гауссиан
5) с некоторой периодичностью используем адаптивный контроль плотности

### 2.2.Challenges of training 3DGS on a consumer GPU

Опять же большой объем памяти нужен на GPU не только для параметров гауссиан, но и для градиентов + 2 доп версии в качестве состояния оптимизатора.

Можно попробовать Unified Virtual Memory - объединить память CPU и GPU, 

Также есть техника Zero-Offload, чтобы процесс Adam перенести на CPU, а остальное считать на GPU.


Основная идея: разделить параметры гауссиан на критические (позиция, вращение, масштаб) — лежат на GPU и некритические (непрозрачность, цвет - SH) — лежат на CPU (но подгружаются по мере необходимости)

Кроме того использовать локальность: так как гауссианы двух видов i и j могут пересекаться, то есть смысл организовать обучение так, чтобы увеличить кол-во возможных пересечений
